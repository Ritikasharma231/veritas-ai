# Model & Data Documentation

## Datasets

| Source | Origin | License / terms | Notes |
|---|---|---|---|
| WELFake | Weibo / Kaggle-derived English fake-news corpus (~72k) | Research use; see `github.com/ashleyou/WELFake` | Labels: fake/real; contains publisher-domain field used for leakage checks |
| `mrm8488/fake_news` (HF) | `news.csv` style corpus used by public HF fake-news models | Check HF dataset card | Columns: title, text, label |
| Custom CSV | `--source csv` | User-provided | Must contain text + label columns |

Normalization maps heterogeneous labels to canonical `Real` / `Fake`; rows with
other labels (e.g. half-true, pants-on-fire from LIAR-style data) are dropped —
a documented limitation, since collapsing them would inject label noise.

## Preprocessing (`ml/data/download_data.py`, `ml/preprocessing/`)

1. Schema normalization → `text`, `title`, `label`, `source_id`, `source`
2. Label canonicalization; drop non-binary labels
3. Length filter (30–100k chars), missing-value handling
4. Exact-duplicate removal on normalized `model_text` (`title + "\n\n" + text`)
5. Seeded stratified splits with **source-group holdout**: all rows sharing a
   `source_id` stay in one split (train 70% / val 15% / test 15%)
6. Runtime cleaning (`backend/app/ml/text_utils.py`): Unicode NFKC, HTML strip,
   URL removal, control-char removal, whitespace normalization — casing and
   punctuation preserved deliberately

## Training (`ml/training/train_transformer.py`)

- HF `Trainer` + `AutoModelForSequenceClassification`
- AdamW (`optim="adamw_torch"`), linear LR decay + warmup, weight decay
- `max_grad_norm=1.0` gradient clipping
- Early stopping on validation **macro-F1** (patience 1 epoch)
- Best checkpoint selection (`load_best_model_at_end`)
- Metrics: accuracy, macro/weighted precision-recall-F1, ROC-AUC,
  confusion matrix, per-class report — computed on the untouched test set
- Reproducibility: `--seed` fixes python/numpy/torch RNGs
- CPU fallback automatic; `--fp16` only when CUDA available

## Evaluation (`ml/evaluation/evaluate.py`)

Produces `ml/reports/evaluation_metrics.json`:
`accuracy, precision_macro, recall_macro, f1_macro, f1_weighted, roc_auc,
confusion_matrix, labels, classification_report, per_class{precision,recall,f1,
support}, train/val/test row counts, hyperparameters, timestamps`

`train_transformer.py` additionally writes `comparison_report.json` merging
transformer + TF-IDF baseline results.

## Inference & explainability (`backend/app/ml/`)

- Tokenizer: model's own tokenizer; truncation at `MODEL_MAX_LENGTH` (512),
  attention masks generated by the tokenizer
- Probabilities: softmax over class logits; `id2label` read from model config,
  normalized to canonical `Fake`/`Real`
- **Attribution**: gradient-based token saliency — backprop the winning-class
  logit to input embeddings, aggregate |∇| per token, map through offset
  mapping to surface words; aggregated to sentence level. Labeled honestly as
  `gradient_token_attribution` — it shows what the model *used*, not what is
  *true*.
- **Linguistic signals**: rule-based features — exclamation/question density,
  all-caps ratio, sensational/urgency/emotional/clickbait lexicons, hedging &
  subjectivity markers, sentence-length variance (burstiness proxy),
  vocabulary diversity, punctuation density → `sensationalism_score` (0–1)

## Model selection

Candidates evaluated conceptually against constraints:

| Candidate | Params | CPU inference | Label clarity | Decision |
|---|---|---|---|---|
| distilbert-base-uncased | 66M | fast | needs fine-tune | best local fine-tune default |
| roberta-base | 125M | moderate | needs fine-tune | supported via `--model` |
| microsoft/deberta-v3-base | 184M | slower | needs fine-tune | supported via `--model` |
| hamzab/roberta-fake-news-classification | 125M | ~1–2 s/text CPU | explicit FAKE/TRUE | **default inference checkpoint** |
| TF-IDF + LogReg | — | instant | n/a | baseline + comparison |

Default inference uses the pretrained RoBERTa checkpoint because it is the only
candidate verified to expose explicit class labels and run acceptably on CPU.
When you fine-tune locally, set `MODEL_PATH` — the app then uses your checkpoint
and reports `locally_finetuned: true` plus real metrics from `ml/reports/`.

## Known limitations

- Binary framing; cannot represent satire/opinion/mixed content
- English-centric; degrades on other languages
- Label noise inherited from source datasets
- Attribution is saliency, not causal evidence or factual verification
- Small inputs (<~30 words) produce less reliable predictions
